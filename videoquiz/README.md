# 一頁式問卷三件套（可複製）

這個資料夾是**模板**。要再做一份問卷（課前調查、活動報名、需求盤點⋯），複製它改五個地方就好。
老師 2026-09-27：「以後可能會做很多這類型的問卷，目的是要收 email 或者統計。」

| 檔 | 管什麼 | 複製時要改 |
|---|---|---|
| `index.html` | 填答頁（受測者看的） | `SHEET_API`、`QS`、`source`、標題文案 |
| `apps-script.gs` | 後端（寫試算表、回人數、回統計） | `SHEET`、`HEAD`、`STATS_Q` |
| `stats.html` | 統計頁（自己看的，圓餅圖） | `SHEET_API` |
| `poster.png` | 感謝頁的招生海報 | 換圖或刪掉 |

**這份問卷本身的規劃真相**在 productkit：
`5-企劃與產品手冊/productkit/10-直銷團隊-天麗專案/短影音/04-課前調查.md`
（含第一批 n=19 的回收結果與四條預期的驗證）。

## 先決定：這份問卷主要是「收 email」還是「看統計」

兩個目的會拉出不一樣的版面，**先想清楚再動手**，不然會做出一份兩邊都不到位的東西。

| | 收 email 為主 | 看統計為主 |
|---|---|---|
| 題數 | **越少越好**（3 題以內），每多一題流失一批 | 5–8 題無妨，答題本身就是目的 |
| email | 位階拉高，但**仍然選填** | 沉在配角層（桃色淡面） |
| 鉤子 | 「留了就寄 ⚪⚪」——**承諾的東西必須真的會寄** | 「我想照你們的程度備課」 |
| `stats.html` | 可留可不留 | **必要**，是整份的產出 |
| 接 LaunChill | 要（`NEWSLETTER_API` + `action=subscribe`） | 可選 |

📌 **實測數據支持「email 一律選填」**：天麗這份 19 人裡 **14 人（74%）主動留了 email**。
選填沒有讓名單崩掉，卻讓 5 個沒信箱的人也進得來。**不要為了名單去擋人。**

## 複製步驟（約 20 分鐘）

1. **複製資料夾**：`cp -r videoquiz <新名字>`，網址就是 `https://lp.atpifit.com/<新名字>/`。
2. **開一份新的 Google 試算表** → 擴充功能 → Apps Script → 把 `apps-script.gs` 整份貼進去，
   蓋掉原本的 `myFunction`。改 `SHEET`（分頁名）、`HEAD`（欄位）、`STATS_Q`（題目與選項）。
3. **部署** → 新增部署作業 → 網頁應用程式 → 執行身分＝**我**、
   具有存取權的使用者＝**🔴 任何人**。複製結尾是 `exec` 的網址。
4. **把那條網址貼進 `index.html` 和 `stats.html` 的 `SHEET_API`**（兩支都要）。
5. **改 `index.html` 的 `QS`**（題目）與 `source`（名單來源標記），以及標題／說明文案。
6. **commit + push**，等 GitHub Pages 生效 1–2 分鐘。
7. **驗收**：自己填一筆 → 試算表有列 → `stats.html` 數字跳動 → **把測試那列刪掉**。

## 🔴 已經踩過的坑，不要再踩一次

**部署**
- **存取權限一定要「任何人」。** 設成「只有我」時端點回 403 登入頁，
  填表的人全部送不出去，**而頁面看起來一切正常**——這是整條流程最會出錯的一顆。
- **改完程式要重新部署**：部署 → 管理部署作業 → 鉛筆 → 版本選「**新版本**」。
  沒選新版本＝線上跑的還是舊的，改了等於沒改。
- **repo 的 `.gs` 只是副本，沒有 clasp。** 一定要手貼回編輯器。
  貼之前先把編輯器現有內容存一份，否則會蓋掉「只改在編輯器沒同步回 repo」的東西。

**寫程式**
- **不要在 `.gs` 裡用正規表示式字面值。** 貼進 Apps Script 編輯器時 regex 最容易被貼壞，
  2026-09-26 第一次部署就倒在 `Invalid regular expression flags`。要驗字串就用逐字元迴圈
  （見 `safeCb_()`）。
- **統計頁用 JSONP，不要用 `fetch`。** Apps Script 的 GET 會轉址到 googleusercontent，
  跨網域 fetch 讀回來不穩。做法＝塞一個 `<script src=...&callback=xxx>`。
- **`STATS_Q`（後端認的選項）和 `QS`（前端顯示的題目）必須逐字一致**，順序也要一樣。
  不一致的答案會全部落進「其他」桶，而且不會報錯。

**資料**
- 🔴 **上線後才加欄位，會讓舊列整排錯位。** 天麗這份就踩了：加「姓名」欄之後，
  9/26 那兩列的 email 掉在姓名欄、最後一題掉出表外。
  修法看 `apps-script.gs` 的 `cleanupLegacyRows()`（手動跑的一次性函式）。
  **能避就避——欄位一次想好再上線。**
- **測試列一定要刪。** 測試通常五題都選最差，19 個人裡混一筆就足以把圓餅圖拉歪。

**版面**
- 🔴 **字級全部走 `rem`，不要寫回 `px`。** 右上角那顆「放大字」是改 `html` 的 `font-size`，
  一旦有 px 寫死，那顆鈕對該元素就失效。受眾不熟網路時這顆鈕是必要的。
- **統計頁檔名叫 `stats` 不叫 `admin`**：這頁沒有任何權限控制，
  叫 admin 會讓後來的人誤以為它受保護，然後放心把名單塞進去。

## 統計頁公開是安全的，但要知道安全在哪

`stats.html` 沒有密碼。**姓名與 email 漏不出去不是靠「回傳值裡沒放」**，
是靠 `stats_()` 的 `getRange` 只框答案欄——**名單那兩欄根本不進記憶體**。
這是讀取範圍的結構保證，之後有人想加功能漏名單，得先動那行 `getRange`，會被看見。

**要做人名對照，就另開一支端點、那支才上金鑰。不要把名單塞回 `stats`**——
一塞回去，這個保證就沒了。

⚠️ 要自己秤的是觀感：彙總數字本身會被看見（「這群人 32% 腳本完全沒概念」）。
如果問卷對象是特定單位、被他們自己翻到會尷尬，就在 `doGet` 的 stats 分支加金鑰檢查。

## 題目怎麼出（驗證過的規則）

- **選項一律三個，不要五個。** 受眾不熟網路時，刻度越細亂選機率越高。
- **選項講「做得到什麼」，不用程度形容詞。**
  ✅「裝了，會一點點」　❌「中級」——後者要對方先自評再翻譯成等級，多一層猜測多一層噪音。
- **最後放一題「你最想先解決哪一個」。** 這題比任何能力自評都準，
  而且直接告訴你課堂時間要押在哪。
- **放一題「你已經做過幾次」定錨。** 天麗這份就是靠它推翻了「這群人是新手」的假設
  （79% 已發過 4 支以上），整堂課的痛點因此重寫。
- **答完一題自動捲到下一題**，底部固定「已答 N / M」。這群人最容易漏的是「下面還有」。
